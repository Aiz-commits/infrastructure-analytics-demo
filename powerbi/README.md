# Power BI management dashboard (Phase 2.5)

Streamlit is the working tool, and this report is the management view. It answers one question: **how much has been billed against the contract, where are the problems, and how fast do we decide?**

Spec: `docs/superpowers/specs/2026-11-25-powerbi-dashboard-design.md`.

| Page | Source | Footer label |
|---|---|---|
| 1. Live app activity | Neon: decisions saved by the live app | Live app history — synthetic examples only |
| 2. Portfolio overview | Synthetic portfolio | Synthetic portfolio — generated, not real |
| 3. Findings | Synthetic portfolio | Synthetic portfolio — generated, not real |
| 4. Approval speed | Synthetic portfolio | Synthetic portfolio — generated, not real |

The synthetic portfolio has 4 projects, 3 fictional contractors and 31 statements, with 10 planted problems. It is generated by `scripts/portfolio.py`. Every finding in it comes from the same Python checks the app uses, and Power BI only counts and sums them.

## What is in this folder

| File | Use |
|---|---|
| `infrastructure_dashboard.pbix` | The finished report. Open it in Power BI Desktop (free, Windows) to click through the 4 pages |
| `infrastructure_dashboard.pdf` | The same report as a PDF, for anyone without Power BI |
| `measures.dax` | Every measure, with the table it belongs to |
| `theme.json` | Dark report theme (View → Themes → Browse for themes). The colours were checked to stay distinguishable for colour-blind readers |
| `readonly_role.sql` | Read-only Neon login for Power BI (views only) |
| `data/*.csv` | The three portfolio views as CSV, so you can build without Neon |
| `expected_totals.json` | The numbers your cards must show (reconciliation) |

Regenerate the CSVs and totals after changing `scripts/portfolio.py`. A test fails if you forget.

```bash
python -m scripts.portfolio --csv powerbi/data --expected powerbi/expected_totals.json
```

## 1. Fill the database (once)

1. Put `DATABASE_URL = "..."` in `.streamlit/secrets.toml`. It is the same Neon string as the app's.
2. Load the portfolio. It replaces only the `portfolio_*` rows, so the live history is untouched:

```bash
python -m scripts.portfolio --load
```

3. In the Neon SQL Editor, run `readonly_role.sql` after replacing the password.

## 2. Connect Power BI Desktop

**Option A: Neon (live page plus portfolio).**
1. Get data → **PostgreSQL database**.
   - Server: the host from your connection string. Use the host **without `-pooler`** (Neon dashboard → Connect → turn off "Connection pooling"). Pooled connections can break Power BI's queries.
   - Database: `neondb`.
   - Data connectivity mode: **Import**.
2. Credentials: Database tab, user `powerbi_reader`, plus the password. Keep "encrypted connection" on, because Neon requires SSL.
3. In the Navigator, tick only the **5 views**: `v_controller_decisions`, `v_controller_findings`, `v_portfolio_projects`, `v_portfolio_statements` and `v_portfolio_findings`. Click **Transform data**.

**Option B: offline (portfolio pages only).** Get data → Text/CSV, and pick the three files in `powerbi/data/`. In Power Query, set the file origin to `65001: Unicode (UTF-8)`.

**In both cases, check the types in Power Query:**
- Money columns (`works` … `ttc`, `contract_ttc`, `billed_ttc`, `cumulative_ttc_billed`, `stated`, `expected`, `difference`): **Fixed decimal number**.
- `days_to_decision` and `minutes_to_decision`: Decimal number.
- `*_at` columns: Date/Time. They are UTC.
- `start_date`: Date.
- If Windows uses a French or Moroccan locale, the CSV decimals (`1234.50`) may be misread. Use Change type → **Using locale… → English (United States)** for the number and date columns.

## 3. Model

In Model view, create the relationships below. All are single direction, one → many.

```
v_portfolio_projects[project]       1 ──→ * v_portfolio_statements[project]
v_portfolio_statements[statement_id] 1 ──→ * v_portfolio_findings[statement_id]
v_controller_decisions[id]          1 ──→ * v_controller_findings[run_id]
```

- Use `v_portfolio_projects[project]` and `[contractor]` for slicers. Do not use the copies in the other views, because they would not filter across tables.
- Then add the measures from `measures.dax`, and apply `theme.json`.

## 4. Pages

The style is inspired by FinceptTerminal: dark, dense, a KPI strip on top, and one alert colour.

1. **Live app activity.**
   - Cards: Runs Saved, Approval Rate, Problems Flagged, AI Text Share, Median Minutes to Decision.
   - Column chart: Runs Saved by `decided_at` (day).
   - Stacked bar: Runs Saved by `file_name` and `decision`.
   - Bar: Live Review Findings by `check_group`.
2. **Portfolio overview.**
   - Cards: Contract Value, Billed TTC, % Contract Billed, Pending Statements.
   - Clustered bar by project: Contract Value next to Billed TTC.
   - Line chart: x = `statement_number`, y = `cumulative_ttc_billed` (Maximum), legend = project.
   - Slicers: contractor, project.
3. **Findings.**
   - Matrix: rows = contractor, columns = `check_group`, values = Review Findings, with background colour from conditional formatting using the sequential blues.
   - Bar: Difference Amount DH by `check_group`.
   - Table: project, statement, title, stated, expected, difference, evidence. Filter it to severity = REVIEW.
4. **Approval speed.**
   - Cards: Median Days to Decision, % Decided Within Target.
   - Bar: Median Days to Decision by contractor.
   - Column chart: Statements by decision and contractor.
   - Scatter: `statement_number` against `days_to_decision`.

Put the matching Source Label measure in a card at the bottom of every page.

## 5. Reconcile (before you share anything)

Compare your cards with `expected_totals.json`. All values must match to 0.01, and percentages are shown ×100 in the file.

| Card | Key in `expected_totals.json` |
|---|---|
| Contract Value / Billed TTC / % Contract Billed | `portfolio.contract_ttc` / `billed_ttc` / `pct_contract_billed` |
| Review Findings, Rejected Statements, Pending | `portfolio.review_findings` / `rejected_statements` / `pending_statements` |
| Median Days to Decision, % Within Target | `portfolio.median_days_to_decision` / `pct_decided_within_target` |
| Per project and per contractor | `projects.*`, `contractors.*` |

For the live page, the Runs Saved / Approved / Rejected cards must equal the "Public history" totals on the live app after a refresh.

A difference means a wrong relationship, type or measure. Fix the model; never type the numbers in by hand. You can also use the finance plugins' Excel-check skill on your PC to compare an exported table with this file.

## 6. Share

- Default: screenshots in `screenshots/powerbi_*.png`, a File → Export → PDF, and a short screen recording for LinkedIn.
- With a university Microsoft 365 account: Publish to a workspace and share it with the university. "Publish to web" is often disabled by tenant admins.
- The `.pbix` file stores no passwords, because Power BI keeps credentials outside it, so committing it is safe. Re-check before you commit anyway.

## Reusing this in Excelium

The report depends only on the **view contract** below: view names and columns, in this order. Excelium can reuse `measures.dax`, `theme.json` and the page layout by producing views with the same names and columns from its own tables. To point the report at them, use Transform data → Data source settings → Change source.

| View | Columns |
|---|---|
| `v_controller_decisions` | id, decided_at, decision, file_name, project, statement_number, read_method, language, ai_used_text, edited, rule_version, review_count, warning_count, opened_at, minutes_to_decision |
| `v_controller_findings` | run_id, decided_at, decision, file_name, language, check_id, check_group, severity, title, stated, expected, difference |
| `v_portfolio_projects` | project, contractor, contract_ttc, start_date, billed_ttc, statements |
| `v_portfolio_statements` | statement_id, project, contractor, statement_number, works, previous, cumulative, retention, net, vat, ttc, cumulative_ttc_billed, contract_ttc, submitted_at, opened_at, decided_at, decision, days_to_decision, review_count, warning_count |
| `v_portfolio_findings` | statement_id, project, contractor, statement_number, decision, check_id, check_group, severity, title, stated, expected, difference, evidence |

`check_group` is one of: `arithmetic`, `continuity`, `sequence`, `missing value`, `uncertain label`. Tests in `tests/test_history.py` and `tests/test_portfolio.py` pin this contract, so a change here must update both the tests and this table.

**Privacy rule for Excelium:** if Excelium holds real data, its report uses its **own** database and a private workspace. It never connects to this demo's Neon, and is never published to the web or shown on LinkedIn.
